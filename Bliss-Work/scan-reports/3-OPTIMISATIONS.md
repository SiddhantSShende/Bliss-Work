## Go services
- **O-WS-1 [Med] Every broadcast pod writes the same outbox entries** — `ws-gateway/internal/fanout/fanout.go:66-81,174-188`. Each pod has its own consumer group and ZADDs identical members per recipient → Redis write load scales with pod count, not traffic. **Fix:** make `WS_FANOUT_MODE=routed` the default, or elect one writer.
- **O-WS-2 [Low] Replay `hello` blocks readLoop so pongs aren't processed** — `server/conn.go:293-312,553-604` (ping at `:242-265`). A slow replay/hydrate makes the 10 s ping time out and drops the client. **Fix:** run `onHello` on its own goroutine.
- **O-WS-3 [Low] Hydrate, delivery and blocklist HTTP clients use default transport (2 idle conns/host)** — `hydrate/hydrate.go:46`, `delivery/delivery.go:101`, `blocklist/blocklist.go:51`. `push.Client` already tuned to 32; reconnect storms churn TCP. **Fix:** share one tuned Transport.
- **O-WS-4 [Low] Hot-path allocations** — `fanout/fanout.go:148,167`, `contract/payload.go:58-83`, `hub/hub.go:224-247`. Event decoded twice (Event + map to delete `members`); `Hub.Fanout` allocates a slice and observes a histogram per recipient. **Fix:** strip `members` at byte level; sample histogram.
- **O-WS-5 [Low] Session-revoke consumer uses a new random Kafka group on every pod start** — `revoke/consumer.go:62-63`. Orphaned groups; revocations while pod is down skipped (LastOffset). **Fix:** stable per-replica group id.
- **O-WS-6 [Low] `?token=` query string accepted on all HTTP routes** — `server/server.go:358-365`. Tokens in proxy/access logs; only `/ws` needs it. **Fix:** restrict to `/ws`.
- **O-NOT-1 [Low] `markReadByTasks` emits one outbox INSERT per flipped row** — `notification-svc/internal/httpapi/httpapi.go:593-597`. **Fix:** one unnest multi-row insert.
- **O-MSG-1 [Low] Redundant indexes on hottest tables** — `messaging-svc/migrations/0001_init.sql:65` (`idx_messages_conv_seq` duplicates UNIQUE at :35), `0002_channels.sql:40` (duplicates `UNIQUE (channel_id, seq)`). Two identical b-trees maintained per insert. **Fix:** drop in a new migration.
- **O-MSG-2 [Low] `SendMessage` updates the same conversations row twice** — `store/messages.go:69` (no-op DO UPDATE upsert), `:520` (seq_counter UPDATE); name lookups (Redis) run after the row lock. **Fix:** `ON CONFLICT DO NOTHING` + SELECT; resolve names before locking.
- **O-MSG-3 [Low] Redis on the request path: 2 sequential limiter round trips + cache lookups inside open txs, no breaker** — `middleware/ratelimit.go:150-156`, `ratelimit_shared.go:177-190`, `store/messages.go:614`, `store/channels.go:880-899`. Redis outage = up to 2×100 ms per request and 50 ms per send under the conversation row lock. **Fix:** breaker, one script for IP+user, fetch names before tx.
- **O-MSG-4 [Low] `HydrateMessages` uses 3 queries in 2 txs** — `store/hydrate.go:51-170` (runs on every reconnect replay). **Fix:** one joined query.
- **O-MSG-5 [Low] `whereami` uncached; singleflight shares first caller's context** — `api/geocode.go:96,124-170`. Every call hits the paid IP-geolocation provider; first caller's disconnect fails all waiters. **Fix:** cache minutes; detached time-boxed ctx.
- **O-MSG-6 [Low] GCM cipher rebuilt per operation; DEK cache misses not single-flighted** — `internal/crypto/crypto.go:696,509-540`. **Fix:** cache AEAD in DEK entry; singleflight.
- **O-RB-1 [Low] Exporter consumer group has no `StartOffset`** — `region-bridge/internal/bridge/export.go:86-97`. kafka-go defaults new group to FirstOffset → first deploy re-exports retained history to JetStream and peer Kafka (notification-svc sets LastOffset for this). Config group id not checked. **Fix:** `StartOffset: LastOffset` or a switch.
- **O-GO-1 [Low] HTTP servers set only `ReadHeaderTimeout`** — `ws-gateway/cmd/ws-gateway/main.go:279`, `notification-svc/cmd/server/main.go:112`, `messaging-svc/cmd/server/main.go:359`, `region-bridge/cmd/bridge/main.go:249`, `sticky-relay/cmd/sticky-relay/main.go:151`. No `IdleTimeout` → idle keep-alives forever; slow bodies (8 MiB `/internal/push`, uploads) can trickle. **Fix:** `IdleTimeout` + `ReadTimeout` where not streaming.
- **O-GO-2 [Low] jwtauth: case-sensitive "Bearer " and text/plain JSON errors** — `services/shared/jwtauth/jwtauth.go:98-115`. ws-gateway accepts any case; `http.Error` with hand-written JSON returns `text/plain`. **Fix:** case-insensitive scheme; shared JSON error writer.

## Python services
- **O-SH-1 [Med] JWKS cache fails closed when auth-svc unreachable (no stale-while-error)** — `services/shared/jwks_auth/jwks_auth.py:102`. After the 5-min TTL a failed refresh raises, breaker returns 503 for every authenticated request platform-wide though cached keys are valid; lock taken on every request, not only refresh. **Fix:** serve stale keys on failure (hard max age); lock-free fast path.
- **O-SH-2 [Low] crypto DEK cache: no single-flight on version path, never evicts** — `services/shared/crypto/crypto.py:430`. Concurrent misses each query + Vault unwrap; `_dek_cache`/`_locks` grow with orgs×versions. **Fix:** per-(org,version) lock; prune expired.
- **O-AUTH-1 [Low] Per-request middleware overhead, five Redis clients** — `auth-svc/app/main.py:105-140`, `rate_limit.py:205`. Six stacked `BaseHTTPMiddleware` layers; five separate Redis clients (slowapi, sensitive limiter, captcha, two i18n caches); sensitive limiter 2–3 round trips; in-process limiter runs O(n) `_purge_expired` on every request once >100 k buckets. **Fix:** pure ASGI middleware, one Redis client, single INCR + Lua expire.
- **O-AUTH-2 [Low] Argon2 hashes never upgraded** — `security/passwords.py:58`. `check_needs_rehash` never called, so raised cost parameters never apply to existing hashes. **Fix:** rehash on successful login.
- **O-AUTH-3 [Low] `reproject` inserts outbox rows per member** — `routes/internal.py:85`. Up to 5 000 sequential INSERTs in one tx and decrypts every avatar needlessly. **Fix:** multi-row insert, lighter query.
- **O-TASK-1 [Low] Transition handlers / availability / schedules** — `task-svc/app/routes/transitions.py`, `availability.py`, `schedules.py`. ~5 round trips per transition across four near-identical handlers; `/tasks/availability` aggregates the whole org per call, uncached; `list_schedules` unbounded with serial decrypt. **Fix:** single CTE `UPDATE…RETURNING` + outbox; short TTL cache; paginate.
- **O-EW-1 [Low] Provider send encodes attachments integrations-svc will reject** — `email-worker/app/provider_mail.py:98-116`, `config.py` (`mail_attachment_budget_bytes`=10 MiB), `integrations-svc/app/providers/microsoft.py:131-141`, `middleware.py:26`. Relay budget 10 MiB raw vs Graph inline 3 MiB vs integrations body cap 5 MiB → base64+JSON (~13 MB, on the loop) POSTed only to get 413/400, then SMTP anyway. **Fix:** skip `provider_send` above 3 MiB.
- **O-EW-2 [Low] Jinja templates recompiled per email; SMTP connection per message** — `templates.py:355,396`, `mailer.py:210`. **Fix:** module-level templates; persistent `aiosmtplib.SMTP`.
- **O-TEL-1 [Low] `org_summary` scans all of today's events twice** — `telemetry-svc/app/routes/analytics.py:60-80,292-300`. `SELECT DISTINCT user_id` + per-user COUNT on each admin-grid load. **Fix:** members from `user_sessions`/roster; short-TTL cache.

## Web frontend
- **O-WEB-1 [Med] "charts" chunk is really framer-motion, modulepreloaded by index.html; config comments stale** — `apps/web/vite.config.ts:~120-187` (manualChunks, `chunkSizeWarningLimit`), `apps/web/dist/index.html`; framer-motion imported by Modal, ProfileMenu, ChatThread, ThreadView, MailListRow, BrowserStickies. Comments say charts are analytics-only and `index` ≈239 kB; actually framer-motion (114 KB) is eager and `index` is 484 KB — ≈880 KB uncompressed eager JS before AppShell; the 350 KB budget isn't enforced. **Fix:** `LazyMotion`/`m` + `domAnimation` or CSS; rename chunk group; update comments.
- **O-WEB-2 [Low] Cache Storage + service workers wiped on every page load** — `apps/web/src/main.tsx:8-21`. **Fix:** run once behind a flag or remove.
- **O-WEB-3 [Low] CSP `connect-src` allows any https/wss host and localhost in prod** — `apps/web/index.html:27` (also `infra/caddy/Caddyfile:260`, `Caddyfile.waf:319`). Makes connect-src ineffective vs exfiltration. **Fix:** inject concrete origins at build; drop localhost for prod.
- **O-WEB-4 [Low] Telemetry sync on two timers; hidden tabs still post every 30 s** — `packages/app/src/lib/telemetry.tsx:291-312` (`HIDDEN_HEARTBEAT_MS`=5 min defeated by 30 s flush); on desktop sends keepalive POSTs even when empty. **Fix:** one timer; retune on visibility.
- **O-WEB-5 [Low] Parallel 401s each trigger their own refresh** — `packages/shared/src/api/client.ts:272-275,1346-1349`. Serialized so safe, but each is a wasted rotation. **Fix:** retry directly if token already changed.
- **O-WEB-6 [Low] ThemeProvider context value recreated each render** — `packages/ui/src/theme/ThemeProvider.tsx:208-218`, `App.tsx` `ThemedTree` (re-renders on every navigation). **Fix:** `useMemo` + `useCallback`.

## Mobile

## graph-gw

## Infra
- **O-INF-1 [Med] Availability / alert-rule gaps** — `infra/observability/prometheus/rules/security.yml:163-164`. `CoreServiceDown` covers only auth/messaging/task; no `up == 0` for notification-svc, ws-gateway, graph-gw, telemetry, integrations, sticky-svc, sticky-relay, postgres/redis/kafka exporters, LiveKit, coturn; none for Caddy, TLS cert expiry, Alertmanager delivery failure. - **O-INF-2 [Med] Edge forced to HTTP/1.1 for all traffic** — `infra/caddy/Caddyfile.waf:30` (`servers { protocols h1 }`, workaround for h2 WebSockets in the Coraza wrapper). Browser limited to ~6 conns/origin for the app's many parallel API calls; graph-gw comments assume h2. **Fix:** keep h2; route only WS paths via an h1-only listener, or move the WAF off the ws path.
- **O-INF-3 [Med] LiveKit UDP media range only 201 ports** — `infra/livekit/livekit.yaml:21-22` (`50000-50200`). Port-per-participant transport → a few dozen concurrent calls exhaust it; coturn already widened to ~20 k; `max_participants:100` assumes more. (Inference from LiveKit port behaviour, not repo code.) **Fix:** widen range + ufw rule in `harden-host.sh`, or single-port UDP mux.
- **O-INF-4 [Low] nginx emits duplicate `Cache-Control` on static assets** — `infra/nginx/default.conf:96,113,124` (`expires` + `add_header Cache-Control`). **Fix:** keep one.
- **O-INF-5 [Low] Postgres CA private key on prod host beside mounted certs** — `infra/postgres/certs/ca.key`, `docker-compose.prod.yml:595`, `scripts/gen-db-certs.sh` (says keep offline). Anyone with host access can mint trusted DB certs. **Fix:** move `ca.key` off host; mount only `ca.crt`, `server.crt`, `server.key`.
- **O-INF-6 [Low] Compose pinning / `:latest`** — `docker-compose.prod.yml` first-party images default `IMAGE_TAG:-latest` (lines 835–1242) → no rollback target by tag; `electronuserland/builder:wine` (line 201) unpinned while other third-party images are digest-pinned; `docker-compose.yml:107` `axllent/mailpit:latest`. **Fix:** require `IMAGE_TAG`; pin the two.
- **O-INF-7 [Low] No healthchecks on observability containers** — `docker-compose.prod.yml`: otel-collector, prometheus, pushgateway, exporters, cadvisor, alertmanager, tempo, loki, grafana (plus `email-worker`, see B-REPO-3). Containers show `Up` while wedged. **Fix:** add probes.
- **O-INF-8 [Low] Prod Postgres published on `0.0.0.0:5432`** — `docker-compose.prod.yml:611`. Documented as gated by a DOCKER-USER allow-list (memory: ufw can't filter published Docker ports); one missed iptables rule from exposure. **Fix:** bind to a private interface / WireGuard address if remote access is needed.
