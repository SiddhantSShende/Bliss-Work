## 1.2 Purpose and audience

This manual helps workspace members and administrators use the features represented in the BlissWork application. It is intended for people who use the web app, desktop app, or mobile app, including organization administrators who manage members and workspace settings.

The manual uses plain-language instructions and the English labels present in the source code. Some functions depend on the user's role, the deployment configuration, device permissions, or enabled services.

## 1.3 Scope and product overview

BlissWork is a team collaboration product with:

- Direct messages, channels, message attachments, reactions, and notifications.
- Tasks assigned to people or channels, task status actions, projects, schedules, and task analytics.
- Mail-style messaging, drafts, attachments, and mailbox folders.
- Meetings and live audio/video calls, with call chat, notes, participant controls, and optional recording features.
- Member directories, organization administration, account security, and member activity views.
- Web, Electron desktop, and React Native mobile clients.

The web and desktop clients share the main application code. The mobile application has its own navigation and screens; feature parity is not assumed.

## 1.4 Terminology

| Term | Meaning in this manual |
|---|---|
| Workspace / organization | The organization context in which members, channels, tasks, and other data are shown. The UI uses both “workspace” and “organization.” |
| Member | A user with membership in a workspace. |
| Admin / organization admin | A workspace role with administrative controls. The application displays “Admin”; some internal permission names use `org_admin`. |
| Task allocator | The person who creates/sends a task. |
| Assignee | A person or channel member who receives a task. |
| Acknowledge | The assignee's action to accept an allocated task. |
| Leave / withdraw | Task actions that stop a person's participation; the exact action depends on task state and screen. |
| MFA / two-factor authentication | An additional sign-in check using an authenticator code or a backup code. |
| TOTP | A time-based one-time code generated by an authenticator app. |
| Activity record | Activity and session information shown to the member and, for other members, workspace admins. |
| UI verified | Inspected in a running app. No feature was UI verified for this draft. |

## 1.5 Requirements

### Confirmed in repository material

| Client/access method | Confirmed information |
|---|---|
| Web | The application is built as a browser app. The local developer URL in the repository is `http://localhost:5173`; this is not a production workspace URL. A production access URL must be supplied by the administrator. |
| Desktop | Installer assets/documentation exist for Windows 10/11 64-bit, macOS 11 or later, and Linux AppImage or Debian package. The install guide notes the current builds may be unsigned and may trigger operating-system warnings. Follow only the approved installation instructions from your organization. |
| Mobile | Android and iOS client code and native project assets exist. Minimum OS versions, supported devices, and store distribution details are **[To be confirmed]**. |
| Network and services | Normal use relies on access to the deployed application and its configured services. Calls, live updates, and notifications may require real-time network access. Exact firewall, proxy, VPN, and endpoint requirements are deployment-specific and **[To be confirmed]**. |

### Recommendations and unconfirmed requirements

- Use a currently supported browser version and keep the browser or desktop app updated. The exact supported browser/version matrix is **[To be confirmed]**.
- Allow microphone, camera, and screen-sharing permissions only when you intend to use those call features.
- Confirm with your administrator whether your deployment enables billing, integrations, call recording, document previews, or activity collection.
- Desktop build prerequisites such as Node.js and native development tools are for developers/builders, not end users.
