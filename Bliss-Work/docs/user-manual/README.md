## Evidence and wording

- **Code verified** means a route, control, validation, or behavior is present in source. It does not mean a live deployment was exercised.
- **Test evidence** means a test exists for the behavior. The tests were not run as part of this documentation task.
- **UI verified** is reserved for a feature inspected in a running application. No screen could be opened during this review.
- **Partially verified** means the UI or backend implementation exists, but runtime availability, complete permissions, or configuration has not been confirmed.
- **[To be confirmed]** identifies product or deployment details that could not be verified from the available evidence.

Where visible labels are quoted, they are from the English locale unless noted. Labels may change with a future release or localization.

## Using this manual

Start with [Getting started](./02-getting-started.md), then use the module matching the task you want to complete. If a button is missing or a step differs in your deployment, check your role and workspace settings, then contact your workspace administrator. Deployment access and support contacts have not been confirmed.

The code-level inventory and screenshot requirements are in [FEATURE-INVENTORY.md](./FEATURE-INVENTORY.md) and [SCREENSHOT-CHECKLIST.md](./SCREENSHOT-CHECKLIST.md). Unresolved product-owner questions are collected in [OPEN-QUESTIONS.md](./OPEN-QUESTIONS.md).
