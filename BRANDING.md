# BlissWork Branding & Logo Guide

This document explains how the BlissWork logo and branding assets are organized and used across the application.

## Centralized Asset Location

All branding assets are centralized in the `/assets/` directory:

```
/assets/
├── logo.png              # Master BlissWork logo (PNG)
├── index.ts              # TypeScript export of asset paths
└── README.md             # Asset documentation
```

## Logo Usage by App

### Web App (`/apps/web/`)

**Favicon (Browser Tab):**
- Uses SVG favicon at `/apps/web/public/favicon.svg`
- This should be updated to match the centralized logo or replaced with the PNG version

**Navbar Logo:**
- Component: `<Wordmark />` (from `@blisswork/ui`)
- Location: `packages/app/src/features/TopNavbar.tsx`
- Renders the SVG Logo + "BlissWork" text

**Background Branding:**
- CSS gradient mesh (`.brand-mesh`) with brand colors
- Location: `apps/web/src/index.css` and `packages/app/src/routes/AppShell.tsx`
- Colors: Blue (#4F6BF6) to Purple (#9A4DF0) gradient

### Desktop App (`/apps/desktop/`)

**Window/Taskbar Icon:**
- File: `apps/desktop/build/icon.png`
- Should be copied from `/assets/logo.png` during build setup
- Used in: Window title bar, taskbar, system menus
- Reference: `apps/desktop/src/main/assets.ts`

**System Tray Icon:**
- Same `icon.png` file, automatically resized to 16×16 by Electron
- Used across Windows, macOS, and Linux

**Microsoft Store (AppX/MSIX):**
- Store tiles generated from icon: `apps/desktop/build/appx/` directory
  - `StoreLogo.png` (50×50)
  - `Square44x44Logo.png` (44×44)
  - `Square150x150Logo.png` (150×150)
  - `Wide310x150Logo.png` (310×150)
  - `LargeTile.png` (310×310)
  - `SmallTile.png` (71×71)
  - `SplashScreen.png` (620×300)
- Generated by: `apps/desktop/build/gen-appx-assets.sh`
- Command: `npm run icon` (in apps/desktop)

## React Logo Components

Available in `@blisswork/ui` package:

### `<Logo />`
SVG logo mark with theme color support. Renders with CSS variables for color theming.

```tsx
import { Logo } from '@blisswork/ui'

<Logo size={32} />  {/* Default 32px */}
<Logo size={64} className="my-custom-class" />
```

### `<Wordmark />`
Logo + text lockup ("BlissWork" with "Work" in accent color).

```tsx
import { Wordmark } from '@blisswork/ui'

<Wordmark size={26} />  {/* Default 28px */}
```

### `<ImageLogo />`
PNG-based logo for static display without theme styling.

```tsx
import { ImageLogo } from '@blisswork/ui'

<ImageLogo size={32} />
```

## Asset Exports

Centralized exports in `/assets/index.ts`:

```typescript
import { ASSETS } from '../assets'

// Use in component:
const logoUrl = ASSETS.logo  // => '/assets/logo.png'
```

```css
--color-brand-to: oklch(0.6 0.23 302);     /* Purple #9A4DF0 */
```

## Updating the Logo

> **The source of truth is `assets/logo.png` — the real BlissWork mark.
> Every desktop raster is DERIVED from it. Never copy a PNG over `icon.png`
> directly: it must be square, transparent, and ≥256px, and the generator
> handles all three.**
>
> Two things went wrong here historically, and both are fixed:
>
> 1. This page used to say "`cp assets/logo.png apps/desktop/build/icon.png`".
>    That silently broke packaging — `assets/logo.png` is **257×237**, not
>    square, while electron-builder needs a square ≥256×256 icon to generate
>    the `.ico`/`.icns`. Following the step replaced a usable icon with an
>    unusable one and the app fell back to the stock Electron mark.
>
> 2. The fix for (1) made `build/icon.svg` the source — but that file is a
>    hand-drawn 48×48 *approximation*: square-cornered "B", oversized
>    rectangular bubble. So the app shipped a rough copy of its own logo rather
>    than the logo. `build/gen-icons-from-brand.py` now derives every desktop
>    raster from `assets/logo.png` itself.

### To change the logo

1. Replace `assets/logo.png` with the new mark. A transparent background is
   ideal; if it ships on white, the generator flood-fills the background from
   the border (which leaves an enclosed bubble intact) and feathers the
   antialiased edge so the icon doesn't halo on a dark taskbar.
2. Regenerate the desktop rasters:
   ```bash
   python3 apps/desktop/build/gen-icons-from-brand.py   # needs Pillow
   bash apps/desktop/build/gen-desktop-icons.sh         # .icns (macOS)
   ```
   That writes `build/icon.png` (1024²), `build/icon.ico` (16→256) and all
   seven Store tiles.

> **Resolution ceiling:** `assets/logo.png` is 257×237, which is at or above
> native for everything Windows needs (`.ico` tops out at 256) and for the Store
> tiles, but the 1024×1024 macOS slot is upscaled. If a vector or larger master
> ever exists, point `SOURCE` in the generator at it — nothing else changes.

`packages/ui/src/components/Logo.tsx` still draws the older approximated
geometry. It is what both the web app and the desktop app render in-page, so
they match each other; aligning it to the brand mark is a separate change that
affects both.
3. Commit the regenerated assets (they're committed so CI needs no renderer):
   ```bash
   git add apps/desktop/build apps/web/public/favicon.svg \
           apps/desktop/src/renderer/public/favicon.svg assets/logo.png
   ```

Tooling: `librsvg2-bin` is required; `icoutils` and `icnsutils` are optional —
without them the `.ico`/`.icns` step is skipped and electron-builder falls back
to converting `icon.png`.

### Why a hand-built .ico

electron-builder can convert `icon.png` itself, but that gives no control over
the small end of the ladder. This mark has thin details — the chat bubble's tail
and the three dots — that turn to mush when a 1024px raster is downscaled to
16px. `gen-desktop-icons.sh` renders 16/24/32/48/64/128/256 straight from the
vector so they stay legible in the taskbar, Explorer and the Start menu.

### Windows taskbar identity

`app.setAppUserModelId("com.blisswork.desktop")` (in `src/main/index.ts`) binds
the running process to the installed app's identity. Without it Windows treats
the process as a generic Electron host: the taskbar shows the stock Electron
icon regardless of how good `icon.ico` is, pinning targets the wrong thing, and
notifications are attributed to "Electron". The string must match `build.appId`
in `apps/desktop/package.json`, because that is what the installer stamps on the
Start-menu shortcut.

## Brand Colors Usage

- **Web/Desktop UI:** CSS variables automatically applied
- **Logo Component:** Uses `--color-brand-from`, `--color-brand-to`, `--color-accent`
- **AppX Manifest:** `backgroundColor` set to `#6D5BF0` (brand midpoint) in `apps/desktop/package.json`
- **Theme System:** Tailwind v4 @theme block defines all tokens

## Summary

- **Single Source of Truth:** `/assets/logo.png`
- **Web Display:** `<Logo />` or `<Wordmark />` components
- **Static Images:** `<ImageLogo />` component
- **Desktop App:** `apps/desktop/build/icon.png` (should mirror `/assets/logo.png`)
- **Icons:** Generated from SVG source via build scripts
- **Colors:** CSS variables + Tailwind theme

All branding should reference this centralized location. Never hardcode logo paths elsewhere.
